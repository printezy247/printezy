# SEO / AEO / GEO — known gaps and deliberate choices

This file records the things the SEO pass deliberately left alone, so the next
person does not "fix" them by accident.

## `/` and `/ms` are not translations of each other

`/` renders `<Welcome />` — the light, direct-response page whose copy is
hardcoded English (`src/components/landing/Welcome.tsx`). `/ms` renders
`<Landing />` — the full dark site, fully translated.

They were previously declared as en/ms hreflang twins. They are not: the two
pages have different copy, different layouts and different sections. `/` now
declares **no Malay twin** (`msPath: null` in `src/routes/index.tsx`), and the
sitemap gives it no alternates. `/ms` is the true twin of `/home`, and both now
say so.

Fixing this properly needs a real Malay Welcome page plus a translation layer
for its copy. Until that exists, `/` stays English-only in the head and
sitemap, even though the page still links to `/ms` in its nav.

## No CI

There is no `.github/workflows/` in this repo, so a pull request cannot wait on
a check run. Merge on green local `npm test` / `npm run build` only.

## Sitemap deliberately omits `<lastmod>`

None of these routes have a real per-page timestamp to report, and a fabricated
`<lastmod>` teaches crawlers to distrust the whole sitemap. It is added when
there is a real date to put in it.

## `/ezyai` deliberately omitted from the sitemap

While `EZYAI_BOARD_VISIBLE` is false the route redirects, and a sitemap that
lists a redirect earns a crawl warning. The commented entry in
`src/routes/sitemap[.]xml.ts` goes back the moment the board does.

## GEO files are routes, not static files

`/llms.txt` and `/.well-known/security.txt` are generated by TanStack server
routes (`src/routes/llms[.]txt.tsx`,
`src/routes/[.]well-known/security[.]txt.tsx` — the `[.]` escapes the dot, since
a literal dot-directory is skipped by the router generator; content builders in
`src/lib/geo.ts`) so they can never drift from the site data. `security.txt`
computes `Expires` at request time so it is always valid.
